# Five-member Q85 training contract

The selected historical training source is the 2000–2019 NOAA GEFSv12 reforecast: `c00, p01, p02, p03, p04`, 00 UTC initialization, forecast days 1–10, on the 0.5° India grid in `configs/gefs_reforecast_5member_0p5.yaml`. Existing 2021–2023 eleven-member, 1° outputs are retained for provenance, **not** mixed into this training dataset.

`src/preprocessing/five_member_reforecast.py` accepts an already standardized xarray Dataset, checks the five members, grid, lead coordinates and category-required fields, then adds ensemble mean, population spread and valid-member count. It does not read external GRIB/NetCDF files, derive missing variables, align observations or produce labels. The six category field lists currently live in `configs/category_preprocessing_selection.yaml`; that file also contains legacy 2021–2023 acquisition metadata, which is not the selected training scope.

The rainfall label uses the existing composite score: `0.50 × (MAE / training Q90 MAE) + 0.30 × event error + 0.20 × (1 − FSS)`. Bust threshold is now the **training-only Q85 of this composite score** by region, season and lead, with the existing critical-event override. Q90 remains only the component normalization reference. `scripts/fit_rainfall_bust_thresholds.py` requires `--training-end`; `scripts/label_rainfall_bust_events.py` accepts explicit catalogue, registry and output paths. Keep validation/test dates out of threshold fitting.

Remaining before model training: supply one representative five-member file and its variable/units/coordinate schema; implement its reader and unit harmonization; verify observed 0.25° IMD rainfall aggregation to 0.5° and the approved 03 UTC time windows. The present alignment has nine verified rainfall leads unless an extra forecast day is supplied. Then build the six category-specific feature/label tables and connect the six GNN outputs to the existing FastAPI/dashboard contract. No historical data have been relabelled by this change.
