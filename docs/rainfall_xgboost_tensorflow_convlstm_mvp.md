# Heavy-Rainfall Bust Prediction: XGBoost + TensorFlow ConvLSTM MVP

## 1. Scope and status

This specification defines the first machine-learning implementation for the
heavy-rainfall forecast-bust category. It follows the existing architecture and
mathematics documents; it does not redefine the historical bust label.

The modelling pipeline can be implemented and smoke-tested before acquisition
is complete. A reliable fitted model cannot be claimed until sufficient
chronologically distributed, finalized Q95 labels exist. The current partial
pilot is engineering evidence, not a final training dataset.

Acquisition is paused. Existing raw and derived files remain preserved.

## 2. Prediction target and unit

The prediction unit is:

```text
forecast initialization × lead day × all-India region
```

For the approved rainfall pilot there are nine retained lead days because IMD
03-to-03 UTC rainfall is approximated from daily 00-to-00 UTC TIGGE fields as:

```text
aligned rainfall = 7/8 current forecast day + 1/8 next forecast day
```

The binary target is the historical heavy-rainfall bust label generated by the
approved mathematics:

```text
S = 0.50 Z_MAE + 0.30 E_event + 0.20 E_FSS
bust = 1 when S exceeds the selected group Q95 threshold
       or the approved critical-event override applies
```

Labels, observations and retrospective errors are targets/evaluation evidence.
They are never live model inputs.

## 3. Separate category policy

The MVP trains heavy-rainfall-specific component models. Other forecast
categories will receive separate models and source-specific thresholds until
there is enough evidence to justify a category-aware shared model.

NCMRWF and future GEFS samples must not silently share one normalization or Q95
threshold group. Forecast source/model/version remains explicit provenance.

## 4. XGBoost branch

### Purpose

XGBoost models structured issue-time evidence and ensemble uncertainty. It
produces one bust probability per initialization and lead day.

### Input shape

```text
[initialization × lead rows, tabular features]
```

### Frozen MVP feature schema

- Lead day
- Seasonal sine and cosine
- Rainfall ensemble mean, 90th percentile and maximum
- Rainfall ensemble-spread mean and maximum
- Domain fractions exceeding heavy, very-heavy and extreme probability rules
- MSLP mean, minimum and ensemble-spread mean
- 850-hPa U-wind mean and spread
- 850-hPa V-wind mean and spread
- 850-hPa specific-humidity mean and spread
- 500-hPa geopotential-height mean and spread

All imputation/scaling values, if required, are fitted on the training period
only. The builder rejects observation, error, FSS and label columns.

### Parameters

```yaml
objective: binary:logistic
eval_metric: aucpr
max_depth: 6
learning_rate: 0.05
n_estimators: 500
subsample: 0.8
colsample_bytree: 0.8
random_state: 42
n_jobs: -1
```

`scale_pos_weight = negative training labels / positive training labels` is
derived from the training fold only.

## 5. TensorFlow ConvLSTM branch

### Framework

The implementation uses TensorFlow/Keras, not PyTorch. TensorFlow 2.21 supports
Python 3.13. Native Windows TensorFlow is CPU-only; use WSL2 for supported NVIDIA
GPU execution on the RTX 3050. Installation reference:
https://www.tensorflow.org/install/pip

### Input tensor

TensorFlow channels-last layout:

```text
[batch, lead, latitude, longitude, channel]
[batch, 9, 66, 70, 12]
```

The 66 × 70 grid is the approved 0.5-degree common grid with configured domain
bounds treated as cell edges.

### Channel order

1. Rainfall ensemble mean, mm
2. Rainfall ensemble spread, mm
3. MSLP ensemble mean, Pa
4. MSLP ensemble spread, Pa
5. 850-hPa U-wind ensemble mean, m/s
6. 850-hPa U-wind ensemble spread, m/s
7. 850-hPa V-wind ensemble mean, m/s
8. 850-hPa V-wind ensemble spread, m/s
9. 850-hPa specific-humidity ensemble mean, kg/kg
10. 850-hPa specific-humidity ensemble spread, kg/kg
11. 500-hPa geopotential-height ensemble mean, gpm
12. 500-hPa geopotential-height ensemble spread, gpm

Every channel is available from the forecast at issuance. No observed field is
included.

### Normalization and missing values

Per-channel mean and standard deviation are fitted across training
initializations, leads and grid cells only. Validation and test tensors reuse
those frozen statistics. After normalization, missing cells are filled with
zero, which represents the training mean.

### Network

```text
Input [9, 66, 70, 12]
  -> ConvLSTM2D(16 filters, 3×3, same padding, return sequences)
  -> Batch normalization
  -> ConvLSTM2D(32 filters, 3×3, same padding, return sequences)
  -> Batch normalization
  -> TimeDistributed global average pooling
  -> TimeDistributed dense logit
  -> Sigmoid
Output [9 lead-specific bust probabilities]
```

The recurrent direction is forward in lead time. Therefore the Day-k output
does not consume later lead maps. All maps are forecasts available at issuance,
but this causal structure keeps interpretation clean.

### Training parameters

```yaml
batch_size: 2
learning_rate: 0.001
dropout: 0.15
recurrent_dropout: 0.0
l2_regularization: 0.0001
epochs: 100
early_stopping_patience: 12
reduce_lr_patience: 5
```

Training uses binary cross-entropy with a per-lead positive-class weight
calculated from the training fold. Weighting is applied before reducing across
the nine lead outputs. The monitored checkpoint metric is validation PR-AUC.
The model also reports ROC-AUC and Brier score. Batches are not shuffled.

Mixed precision is automatic: enabled only when TensorFlow detects a compatible
GPU. Output probabilities remain float32.

## 6. Chronological split

Random splitting is prohibited because adjacent weather initializations are
strongly correlated. Unique initialization times are sorted and divided:

```text
first 60% -> training
next 20%  -> validation
last 20%  -> test
```

All lead rows from one initialization remain in the same split. The 60/20/20
ratios are configuration defaults for pipeline construction, not evidence that
the current 30-day pilot is adequate for final evaluation.

## 7. Calibration and fusion

XGBoost and ConvLSTM probabilities are calibrated only when a sufficiently
large time-separated validation history exists. The initial calibration method
is sigmoid/Platt calibration because it is more stable than isotonic calibration
on a small validation set.

Fusion uses logistic regression with validation-safe inputs:

```text
P_xgb
P_convlstm
abs(P_xgb - P_convlstm)
```

The fusion model outputs the final heavy-rainfall bust probability. Fusion is
retained only if it improves unseen-period PR-AUC, Brier score and calibration
over both individual branches.

The final binary probability threshold is selected on validation data; it is
not automatically fixed at 0.5. This probability threshold is distinct from
the historical Q95 error threshold used to create training labels.

## 8. Leakage controls

Forbidden live inputs include:

- Observed rainfall
- Forecast error or absolute error
- MAE and RMSE calculated against observations
- FSS or event error calculated against observations
- Critical-event outcome
- Candidate or strict bust label
- Final realized event track, intensity or duration

Feature builders fail when forbidden fields are present rather than silently
omitting them.

## 9. Evaluation

Report at minimum:

- PR-AUC as the primary imbalanced-class ranking metric
- Brier score
- ROC-AUC as a secondary ranking metric
- Reliability/calibration curve
- Probability of detection and false-alarm ratio at the validation-selected
  decision threshold
- Results by lead day
- XGBoost feature importance/SHAP after leakage audit
- XGBoost-only, ConvLSTM-only and fused-model comparison

## 10. Artifacts and reproducibility

Expected artifacts:

```text
models/xgboost/<model-id>.json
models/convlstm/<model-id>.keras
models/fusion/<model-id>.joblib
models/registry/model_manifest.json
```

Each registry entry must include model type, training window, source/model
version, feature/channel schema, configuration hash, split dates, label policy,
metrics and artifact path.

## 11. Current limitation

The implementation can be unit-tested and smoke-trained using synthetic or
partial pilot data. It must not be described as a reliable trained bust model
until acquisition, Q90 normalization, Q95 labelling and chronological multi-year
evaluation are complete.
